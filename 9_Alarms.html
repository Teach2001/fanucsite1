9.1 — Learning Objectives

Fault and Message Diagnosis

Errors occur for a variety of reasons. Understanding the root cause — rather than blindly pressing Reset — is the key to safe and effective troubleshooting. The alarm log and diagnostic tool are your primary resources.

01
Hardware Problems
PHYSICAL CAUSE
A broken cable, damaged tooling, or a faulty sensor. These faults typically require physical inspection and repair before the alarm can be cleared and normal operation resumed.
02
Software Problems
PROGRAM / DATA
An incorrect program, bad data, or an out-of-range parameter. These faults require reviewing program logic, position data, or system configuration to identify the incorrect value.
03
External Problems
ENVIRONMENT
An open safety door, an over-travel condition, or an external device fault. These are often the simplest to resolve — correct the external condition, then reset the controller.
ℹ️
Best Practice: Most errors can be cleared by correcting the problem and pressing the Reset Key on the teach pendant or SOP. However, blindly pressing Reset without understanding the cause will not actually solve the issue — and may mask a more serious fault.
Key Troubleshooting Tools
📋
Alarm Log
View all active alarms at once. The teach pendant title bar only shows the most recent alarm — the alarm log reveals the complete picture and helps determine which fault to address first.
🔍
Diagnostic Tool
Press Shift + DIAG on any alarm to display the possible cause and recommended remedy. Useful for operators to determine whether maintenance intervention is needed.
🕐
Alarm History
Stores the 100 most recent alarms. Review patterns over time to identify intermittent faults. History can also be sorted by alarm type, showing the most recent 50 of each category.

9.3 — DCS Option

Dual Check Safety (DCS)

The DCS Position/Speed Check feature monitors speed and position data using two independent CPUs in the robot controller. Position and speed errors are detected immediately and motor power is shut down.

✓ SAFE POSITION
Robot is within the DCS Cartesian position boundary. Both CPUs confirm valid position. Normal operation continues.
✗ LIMIT VIOLATION
Robot has crossed a DCS position boundary. Motor power is cut immediately. Fault: SRVO-402 DCS Cart. pos. limit
🔧
Procedure 9-6 — Recover from DCS Position Violation:
1. Press Shift + Reset to clear the fault.
2. Jog away from the DCS limit boundary before resuming operation.
9.4 — Singularity

Singularity Error

Singularity occurs in Cartesian/X-Y-Z coordinate mode only. For most six-axis robots, wrist singularity occurs when the axes of Joints 4 and 6 become aligned.

When axis J5 approaches 0 degrees, the robot encounters an infinite combination of J4 and J6 positions that achieve the same Cartesian location — making motion control indeterminate.

ℹ️
NOTE: Singularity is not a FANUC-specific issue — it is an inherent characteristic of all six-axis robots. Joint jogging is not affected by singularity errors.
Procedure 9-7: Recover from Singularity
1
Press COORD — select Joint

Switch from Cartesian coordinate mode to Joint coordinate mode.

2
Move Joint 5 (+/-) 10 degrees

Jog J5 away from 0 degrees to break out of the singular configuration.

3
Return to Cartesian or continue jogging

Once clear of singularity, switch back to your desired coordinate system and resume normal operation.

Singularity — Joint 5 Position vs. Valid Range

J5 NEAR 0° — INFINITE J4/J6 COMBINATIONS

  • Singularity ZoneWhen J5 approaches 0°, J4 and J6 become co-linear. An infinite number of joint angle pairs produce the same Cartesian result.
  • Safe Operating ZoneKeep J5 away from 0° during Cartesian moves. Program paths that avoid the singularity region to prevent runtime errors.
  • Joint Mode ImmunitySingularity only affects Cartesian coordinate motion. Switching to Joint mode allows you to jog freely regardless of J5 position.
9.5 — Chain Failure

Chain Failure Detection Error

The robot controller may be equipped with a dual chain Control Reliable safety circuit. A single component failure does not prevent the stopping action but will prevent further system movement until corrected.

A fault is triggered when one safety chain is in an Emergency Stop condition and the other is not.

SRVO-230  Chain 1 (+24v abnormal)
SRVO-231  Chain 2 (0v abnormal)
⚠️
WARNING: If you reset the chain failure fault without fixing the cause, the same alarm will occur again but the robot can move until it does. Always correct the root cause of the chain failure before continuing — otherwise you risk injuring personnel or damaging equipment.
Procedure 9-8: Reset a Chain Failure Alarm
1
Correct the cause of the alarm

Identify and fix the root cause of the chain failure before proceeding.

2
Create and release a different chain failure

For example, press the EMERGENCY STOP button on the teach pendant and then press RESET to cycle the chain state.

3
Press MENU

Navigate to the main menu on the teach pendant.

4
Select ALARMS

Go to the Alarm screen from the menu.

5
Press F4 RES_1CH

Initiates the single-channel reset procedure.

6
Verify YES — press F4

Confirm the reset prompt: "Reset Single Channel Fault? [NO]" — select YES.

7
Press RESET

Clear the fault from the Active Alarm screen to restore normal operation.

9.6 — Version Identification

Robot F-Number & Version ID

FANUC provides each robot with an F-Number — a unique identification number encoding controller type, robot model, installed options, and sale information. It is located at the base of the robot and on the controller cabinet.

The STATUS Version ID screen displays controller-specific software and hardware details. Have this information ready when contacting the FANUC America Corporation Hotline.

📋
Procedure 9-9: Press Menu → -0- Next → cursor to Status → Version ID → Enter. Press NEXT then F3 ORDER FI to view installed software options.

  • S/W Serial NumberUnique identifier for the software license installed on this controller.
  • Controller & Robot F-NumberUnique robot and controller identification numbers used for support and maintenance.
  • Robot Model & DCS VersionIdentifies the exact robot model and Dual Check Safety software version.
