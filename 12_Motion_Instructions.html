12.3 — Motion Types

Motion Types

The Motion Type defines how the robot will move to the destination. It is set by the motion instruction in the program — not by how the robot was jogged to the position.

J
Joint Motion
% / sec / msec
All required axes move simultaneously to the destination. Each axis starts and stops at the same time. The actual speed depends on the slowest axis. Speed is specified as a percentage of default speed, or timed in ms/sec.
L
Linear Motion
mm/sec / cm/min / inch/min
The TCP moves in a perfectly straight line from start to destination. Speed is specified in velocity units. Programmed at the destination position.
C
Circular Motion
mm/sec / cm/min / inch/min
The TCP moves in an arc through an intermediate position to the destination. Requires TWO half-circles (4 positions) to complete a full circle. Programmed at the intermediate position.
Changing Motion Types (Procedure 12-1)
1
Highlight the motion type

Place your cursor on the J, L, or C character of the motion instruction you want to change.

2
Press F4 [CHOICE]

A popup menu appears listing the available motion types: Joint, Linear, Circular, Circle Arc.

3
Choose the desired motion type

The instruction updates to reflect the new motion type and any relevant syntax changes.

Programming a Circle (Procedure 12-2)
1
Move to the start of the circle

Record as a Joint or Linear move. This brings the robot from anywhere in the cell to the circle's start.

2
Move to the first intermediate position

Record, then highlight the motion type, press F4 [CHOICE], select Circular. The instruction changes to the circular format.

3
Move to the destination position

Place cursor on the destination line, then press F3 [TOUCHUP] to record the destination.

4
Repeat for the second half

A full circle requires two half-circles, each with an intermediate + destination position.

Full Circle Program Syntax
A_CIRCLE 5 LINES
1J P[1] 100mm/sec FINE ; START POSITION
2C P[2] ; INTERMEDIATE 1
  P[3] 100mm/sec FINE ; DESTINATION 1
3C P[4] ; INTERMEDIATE 2
  P[1'] 100mm/sec FINE ; BACK TO START
[End]
12.4 — 12.7 — Positions

Position Information & Types

Positional information describes the location, orientation, and configuration of the TCP when a motion instruction executes. All positional data is recorded automatically when the motion instruction is added.

Positional Information Components
  • UF — User FrameReferences the User Frame the position was recorded with respect to.
  • UT — Tool FrameReferences the Tool Frame the position was recorded with respect to.
  • ConfigurationDescribes the posture of the robot (Flip/NoFlip, Up/Down, Front/Back) upon arrival at the destination.
  • Location (X, Y, Z)Describes the three-dimensional position of the TCP in Cartesian space.
  • Orientation (W, P, R)Rotation about X (Yaw/W), Y (Pitch/P), and Z (Roll/R).
Configuration — Joint Placement
CONFIGURATION IDENTIFIER — (F, L, U, T, 0, 0, 0)
FLIP / NOFLIP
Wrist placement (J5)
LEFT / RIGHT
Arm placement (horizontal)
UP / DOWN
Arm placement (J3)
FRONT / BACK
Robot placement (J1)
Turn number: -1 = -539° to -180° | 0 = -179° to 179° | 1 = 180° to 539°
Position Types — P[n] vs PR[x]
LOCAL
P[n] — Position
Stored within the program. Identified by a number (P[1] to P[32767]). Positions in different programs sharing the same ID have different physical data — they are not correlated. Best for positions used only in one program.
💡
P[1] in PROGRAM_A and P[1] in PROGRAM_B are completely independent positions.
GLOBAL
PR[x] — Position Register
Stored globally in controller memory, accessible by any program. Uses UF:F and UT:F (active frames) rather than fixed frames. Ideal for Home, Pick, Drop, and Repair positions shared across routines.
⚠️
Caution: PR data is shared between all programs. The same PR[x] may resolve to different physical locations depending on the active USER and TOOL frames.
Common Position Register Examples (12.7.1)
🏠
PR[1] — Home
Away from the workpiece transfer area. Robot moves here before the first position and between cycles.
🔧
PR[2] — Repair
Where repair operations are performed. Away from other equipment and the transfer area.
🛡️
PR[3] — Safe
Away from fixtures and transfer area. Move here any time the robot must clear workcell activity.
Creating a Position Register (Procedure 12-4)
1
Move robot to the position

Jog the robot to the exact location you want to record as a Position Register.

2
Highlight the PR to record

Press DATA → F1 [TYPE] → Position Registers to access the PR Data Screen.

3
Name the Position Register

Enter a descriptive name like HOME, REPAIR, or SAFE.

4
Press Shift + F3 RECORD

An "R" appears on the PR line confirming the position has been recorded.

Truly Global PR — Joint Representation (12.7.7)

To make a PR resolve to the same physical location regardless of active frames, convert its data to Joint (degree) representation. The controller uses absolute joint angles — frames become irrelevant.

1
Access the PR positional data

Highlight PR → press F4 POSITION.

2
Press F5 [REPRE]

Select Joint, then confirm with Continue.

📌
Ensure the correct frames are set before recording any Position Register.
12.8 — Speed

Speed

Speed dictates how fast the robot moves during motion. It can be set as part of the motion statement, and further scaled by the General Override on the teach pendant.

General Override (12.8.2)
GENERAL OVERRIDE — TEACH PENDANT (TOP RIGHT)
Location: Green box, top-right of teach pendant
Keys: +% and −% (5% increments by default)
Range: 0.01% (VFine) → 100%
EXAMPLE:
Motion statement: 1000 mm/sec
General override: 75%
Actual speed: 750 mm/sec
⚡
Override can be changed while the program is running without stopping execution.
12.9 — Termination Type

Termination Type

Termination type specifies what the robot does as it approaches the end of a motion. It is programmed at the destination position.

FINE
Fine Termination
The robot stops completely at the destination before moving to the next position. The tool tip accelerates, decelerates as it approaches, and comes to a full stop. Use when precision at the point is critical (pick, place, weld).
CNT 0–100
Continuous Termination
The robot does not stop at the destination — it decelerates, blends the motion, and accelerates toward the next position. CNT0 comes closest to the point (max decel); CNT100 is farthest (min decel). Use for smooth, fast paths.
CNT Value Interactive Demo
ADJUST CNT VALUE — OBSERVE PATH DEVIATION
CNT 50
CNT0 — ClosestCNT100 — Farthest
📌
The severity of the directional change at each taught position and the overall speed determine how strongly CNT affects the path.
⚠️
Warning: There may be inconsistencies between T1 testing and running in Auto. Always run programs in Auto at slow speeds first to verify the path.
Path Correction Approaches
📉
Lower Rate / Speed
Reduce the CNT value (e.g. CNT100 → CNT60) or lower the speed at the position (e.g. 2000 → 1200 mm/sec).
➕
Add a Position
Insert an additional waypoint near the problem area and touch up the original position to better define the intended path.
↔️
Move the Position
Touch up the affected position farther away from the current point to give the blending algorithm more room to work.
