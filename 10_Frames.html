10.2 — Frames Overview

3D Cartesian Coordinate System

A Frame is a 3D Cartesian coordinate system — three planes at right angles to each other meeting at an origin. The FANUC robot uses X, Y, Z for location (measured in mm from the origin) and W, P, R for orientation (degrees of rotation about each axis). Every recorded position is stored as X, Y, Z, W, P, R relative to its reference frame.

Why Frames Matter
  • Reference PointEvery recorded position (X, Y, Z, W, P, R) is measured relative to the origin of the active frame. Change the frame, and all positions shift accordingly.
  • Easy Program UpdatesIf a fixture or tool moves, you update the frame definition — not every individual position in the program. One edit corrects all points.
  • Accurate Path ControlWith a properly defined Tool Frame, Cartesian interpolated motion moves the TCP in a true straight line or arc — not just the robot's faceplate.
  • Flexible JoggingUser and Jog frames let you move the robot aligned to a fixture or part, regardless of how it sits in the cell relative to World.
The Five Frame Types
01
World Frame
DEFAULT / FIXED
Fixed origin at J1/J2 centerline intersection. Basis for all taught positions. Cannot be changed by the user.
02

Defines the Tool Center Point (TCP). Moves the active control point from faceplate to the working tip of the tool.

04

10.4 — World Frame

World Frame

WORLD is the default frame describing the location and orientation of the Tool Center Point (TCP). The default TCP is the center of the faceplate. When recording positional data, the robot measures from the WORLD origin to the tooling and stores it as X, Y, Z, W, P, R.

  • Fixed OriginLocated on the centerline of the J1-axis at the height of the J2-axis centerline. This location never changes.
  • Cannot Be ChangedThe WORLD Frame is the default frame of the robot and cannot be modified by the user. It is the basis for all taught positions and all taught frames.
  • Orientation SensitiveThe orientation of the WORLD frame can change from improper mastering. Ensure the robot is correctly mastered to maintain a reliable world reference.
  • Linear MotionWhen jogging in WORLD coordinate mode, the servo motors maintain linear (straight-line) movement with respect to the tool.

10.5–10.6 — Tool Frame

Tool Frame (TCP)

The Tool Frame moves the active control point from the faceplate to the working tip of the tool (TCP). Once defined, positional data in your programs will be relative to the TCP. Cartesian interpolated motion paths will be based on the TCP, moving it in a true linear or circular path.

ℹ️
Key facts: Default Tool Frame location is the faceplate center (all zeros). Tool Frame data is the physical distance from the TCP back to the faceplate. R30iB controllers: up to 29 Tool Frames. R30iB Plus: up to 253 Tool Frames. Default: 10 schedules.
Six Methods to Define a Tool Frame
3PT
Three Point
Define location only. Touch a common point from 3 different angles.
4PT
Four Point
Precise location with TCP error feedback for iterative correction.
6XZ
Six Point (XZ)
Location + orientation. Use when +Z direction is easier to record.
6XY
Six Point (XY)
Location + orientation. Use when +Y direction is easier to record.
DIR
Direct Entry
Type in measured X, Y, Z, W, P, R values directly from tool specs.
TOOL FRAME — THREE POINT METHOD (PROC. 10-1)
Use when values cannot be measured directly. Touch a fixed reference point from 3 different approach angles. Large rotations (~90°) give the best results.
Approach point 1: UNINIT → Jog tool tip to reference point, Shift + F5 RECORD
Approach point 2: UNINIT → Approach same point from a different angle, Shift + F5 RECORD
Approach point 3: UNINIT → Approach same point from a third angle, Shift + F5 RECORD
After final point → Frame calculated → "New position calculated" displayed

10.7–10.8 — User Frame

User Frame

User Frame is the reference frame for all recorded positional data in a program. User frames are taught by the programmer and can be defined at any location and orientation. Only one can be active at a time. If no User Frame is set, the program uses World Frame's location and orientation.

ℹ️
Key facts: Default User Frame location is the World Frame origin. User Frame data is measured back to the robot origin. R30iB: up to 61 User Frames. R30iB Plus: up to 253. Default: 9 schedules.
Three Methods to Define a User Frame
METHODPOINTS NEEDEDBEST FOR
Three Point3Origin, X direction, Y direction — most common method
Four Point4When origin must be a point other than the reference point used for orientation
Direct Entry0 (manual)When you know the exact X, Y, Z, W, P, R coordinates of the frame
Three Point Method — Key Points
  • Orient Origin PointTouch the point you want as the frame's origin. Defines the X, Y, Z location of the frame relative to World.
  • X Direction PointTouch a point along the desired +X direction. Establishes the X-axis of the frame.
  • Y Direction PointTouch a point in the desired +Y direction. Together with X Direction, fully defines the frame orientation. The X and Y directions establish the orientation of the User Frame.

10.9–10.10 — Jog Frame

Jog Frame

A Jog Frame can be set up at any location with any orientation, giving you a convenient way to jog along a part when it is oriented differently from the World Frame. Positional data is NOT dependent on a Jog Frame — it only affects jogging direction.

  • Up to 5 Jog FramesOne can be active at a time per robot group. Select JGFRM as the coordinate system to activate.
  • Two Definition MethodsThree Point (same as User Frame three-point) or Direct Entry. Must be set up before use.
  • No Effect on Program DataUnlike Tool and User Frames, the Jog Frame does NOT affect recorded positions. It only changes how the robot moves when you are jogging manually.
🔧
To activate JGFRM: Hold Shift + press COORD → set the Jog line to your frame number → press COORD until JGFRM appears in the status bar. The status bar will show SUBSUB LINE 0 T2 ABORTED JGFRM.

10.11 — Frame Data Files

Saving & Restoring Frame Data

Frame data is automatically saved to internal controller memory (SRAM). Always back up to the default device as well — this protects against data loss from corruption or accidental changes. Two files store all frame data.

💾
FRAMEVAR.VR
Stores all Jog Frame data and comments for all frames. Must be loaded to restore Jog Frame configurations and names.
🗄️
SYSFRAME.SV
Stores all Tool Frame and User Frame data. Required alongside FRAMEVAR.VR to fully restore all frame information.
📁
Both Files Required
To completely recover frame data, you MUST load both FRAMEVAR.VR and SYSFRAME.SV. Loading only one results in incomplete restoration.
Procedure 10-10: Save Frame Data
1
Press Menu → File → File

Navigate to the file management screen.

2
Set the default device

Ensure the correct storage device is selected (USB, memory card, etc.).

3
Display any frame screen

Navigate to Tool Frame, User Frame, or Jog Frame setup screen.

4
Press FCTN → Select SAVE

Both FRAMEVAR.VR and SYSFRAME.SV are automatically saved to the default device. Confirmation message will appear.

Procedure 10-11: Restore Frame Data
1
Press Menu → File → File

Navigate to the file management screen.

2
Set default device → Press F2 DIR → select .VR

Filter the directory to show .VR files.

3
Highlight FRAMEVAR.VR → F3 LOAD → F4 YES

Confirm you want to load the file. A confirmation message will appear when complete.

4
Repeat steps 2–3 for SYSFRAME.SV

Filter for .SV files, then load SYSFRAME.SV using the same steps to complete the restoration.
